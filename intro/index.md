# 量潮搜索工程路线图

近景：先做什么、后做什么。远景（为什么做、做成什么样、哪些不做）在意图仓。

## 当前优先

现在最重要的事情是能搜到东西：还没有一个能用的搜索算法。先有一个能用的算法，判据才有作用对象，价值循环才转得起来。

## 排法

一把尺子：**已知的降，未知的升**。别人做过、有现成答案的，照做不探索；我们不知道、但判据押在上面的，优先。

**降（照做即可，不花探索精力）**

- 倒排索引 + BM25 + 中文分词：成熟技术，原型已跑通。
- 幂等、镜像去重、增量更新：标准工程，挂在 lab TODO，动手时照做。
- 引擎选型：已核实一轮，结论已有（tantivy + jieba）。

**升（判据押在上面，我们一无所知）**

判据是「减少 AI 走弯路」，可对 AI 这个搜索用户还没有一条数据：

1. **AI 怎么查**——零查询日志。真实需求分布没人知道，通用搜索引擎那套是人的分布，不能用。它决定该索引什么、怎么排序。
2. **词面检索够不够**——AI 用自己的概念词提问，文档写的是另一个措辞，BM25 按词面匹配必漏，漏了不报错。
3. **什么形态是零弯路**——top-10 路径加分数是给人看的；AI 要整篇、要路径、还是要段落，未知。

## 下一步：采第一批真实 AI 查询

带着本域的真实任务用原型搜，逐条记下来：发了什么查询、命中没有、补了几轮才拿到要的东西。一个实验回答「升」里的 1 和 3，顺手给出第一个弯路数字——命中教程仓 CONTRIBUTING 是 0 步，词面不匹配导致搜了三轮是 3 步。

结果定义「能用的算法」缺什么：缺语义召回、缺返回形态、还是 BM25 就够。缺什么补什么，不照别人的答案补功能。

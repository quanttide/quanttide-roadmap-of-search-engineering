# 量潮搜索工程路线图

近景：先做什么、后做什么。远景（为什么做、做成什么样、哪些不做）在意图仓。本仓只写认知——项目细节归各自正文仓，见 [CONTRIBUTING](CONTRIBUTING.md)。

## 当前优先

现在最重要的事情是能搜到东西：还没有一个能用的搜索算法。先有一个能用的算法，判据才有作用对象，价值循环才转得起来。

## 排法

一把尺子：**已知的降，未知的升**。别人做过、有现成答案的，照做不探索；我们不知道、但判据押在上面的，优先。

**降（照做即可，不花探索精力）**

- 成熟检索技术：倒排 + BM25 + 中文分词，业界答案现成，原型已跑通。
- 标准索引工程：幂等、去重、增量更新，动手时照做。
- 引擎选型：已核实一轮，结论已有，去处在实验室技术笔记。

**升（判据押在上面，我们一无所知）**

判据是「减少 AI 走弯路」，可对 AI 这个搜索用户还没有一条数据：

1. **AI 怎么查**——零查询日志。真实需求分布没人知道，通用搜索引擎那套是人的分布，不能用。它决定该索引什么、怎么排序。
2. **词面检索够不够**——AI 用自己的概念词提问，文档写的是另一个措辞，BM25 按词面匹配必漏，漏了不报错。
3. **什么形态是零弯路**——排名列表是给人看的；AI 要整篇、要路径、还是要段落，未知。

## 下一步：评测

判据替我们选了方法：J 须在真实需求分布上估计，所以不构造测试集——**真值从真实使用行为里来**：搜索之后实际去打开的那份文档，就是期望结果。但真值要先验存在性：hsa 实测去重后 25386 条真实搜索事件，配对率 13.3%——专用搜索 51.0%、shell 仅 7.9%（grep 结果自带内容，不必开文件）。配对率是前置指标，先量出来定考题集的规模与这套评估的适用边界；配上对的子集再抽样校验「打开的就是想要的」。

三条认知：

1. **指标是「到手还要几轮」，不是召回率。** 搜到了但返回形态逼它再补几条命令，照样是弯路——排序和形态共同决定轮数。问法不问「排第几」，问 top 几名里有没有一个能让 AI 直接往下走的结果——连环搜占 43.9%，AI 的模式是快速换词再搜，不是翻页。指标在跑 baseline 之前定死。
2. **一把尺只测一件事。** 排序用离线回放全权测；形态（有片段是否省一轮）回放测不了，薄层人工判「够不够下一步动作」，几十题定方向；重尺（agent 模拟）只做裁决，不作起点。
3. **题源看真值在哪。** 有行为真值的查询直接当题；真值不在文件里的概念查询靠标注，它同时回答词面够不够——回答方式是 baseline 与 LLM 查询改写双组同批对照，同义词短板目前是猜想，让数字说话；只有会话级关联的引用当后验，不出题。

返回形态的最小版本（路径 + 片段 + 范围 + 条数）是轮数的直接杠杆：接口层面的事，不改索引不改算法。数据与题源的事实源在实验室 docs。

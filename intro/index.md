# 量潮搜索工程路线图

近景：先做什么、后做什么。远景（为什么做、做成什么样、哪些不做）在意图仓。

## 当前优先

现在最重要的事情是能搜到东西：还没有一个能用的搜索算法。先有一个能用的算法，判据才有作用对象，价值循环才转得起来。

## 排法

一把尺子：**已知的降，未知的升**。别人做过、有现成答案的，照做不探索；我们不知道、但判据押在上面的，优先。

**降（照做即可，不花探索精力）**

- 倒排索引 + BM25 + 中文分词：成熟技术，原型已跑通。
- 幂等、镜像去重、增量更新：标准工程，挂在 lab TODO，动手时照做。
- 引擎选型：已核实一轮，结论已有（tantivy + jieba）。

**升（判据押在上面，我们一无所知）**

判据是「减少 AI 走弯路」，可对 AI 这个搜索用户还没有一条数据：

1. **AI 怎么查**——零查询日志。真实需求分布没人知道，通用搜索引擎那套是人的分布，不能用。它决定该索引什么、怎么排序。
2. **词面检索够不够**——AI 用自己的概念词提问，文档写的是另一个措辞，BM25 按词面匹配必漏，漏了不报错。
3. **什么形态是零弯路**——top-10 路径加分数是给人看的；AI 要整篇、要路径、还是要段落，未知。

## 下一步：评测——离线回放，真值在日志里

判据替我们选了方法：J 须在真实需求分布上估计，不构造测试集。而真值已经存在——`hermes-session-analyzer` 日志里 3,537 条「搜索 → 紧跟读文件」配对，AI 实际去读的那份文档就是期望结果（研究记录见 lab `docs/2026-10-11-hermes-session-analyzer.md`）。

**题源两类，分工测两个维度：**

1. **排序（离线回放全权负责）**——文件定位类：约 2,000 条带真值的配对（.md、quanttide 仓），每题跑原型，看期望文档排第几：排 1 带片段 = 零弯路，2–10 = 约 1 轮，不在 top-10 = 至少 1 轮。概念词类（memory/session 搜索 210 条）：真值不在文件里，人肉/LLM 标注期望命中——这同时回答未知 2（词面够不够）。回答侧引用（11,310 条 assistant 消息含 .md 引用）只有会话级关联，当后验，不出题。
2. **返回形态（人肉薄层）**——回放测不了「有片段是否就不用再 cat」。同题两版返回（纯路径 vs 路径+前 N 行），人工判「够不够下一步动作」，几十题定方向。v1/v2 僵持才上 agent 模拟，不作起点。

**评测指标 = 到手还要几轮**，不是召回率——搜到了但返回形态让它补 5 条命令，照样是弯路。返回形态最小版本（路径 + 片段 + scope + limit）随评测一起做，它是轮数的直接杠杆，不改索引不改算法。
